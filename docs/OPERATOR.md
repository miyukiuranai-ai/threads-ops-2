# 運用担当者向け 手順書

自分の名義を、このツールに登録して自動運用するための手順です。
**コマンド操作は不要です。** ブラウザだけで完結します。

管理画面: https://threads-ops-app.vercel.app
（IDとパスワードは管理者から受け取ってください）

---

## 全体の流れ

```
1. Meta for Developers で自分のアプリを作る   ← 最初の1回だけ
2. 自分の Threads 名義をテスターに登録する     ← 名義を増やすたび
3. アクセストークンを発行する                 ← 名義を増やすたび
4. 管理画面にトークンを貼り付ける             ← 名義を増やすたび
5. キャラ設定を自分で登録する
```

**1 は最初の1回だけ**です。2回目以降は 2〜4 の繰り返しで名義を増やせます。

---

## 1. Meta for Developers でアプリを作る（最初の1回）

自分の Meta アカウントで作業します。他人のアカウントは使いません。

1. https://developers.facebook.com/ にログイン
2. **マイアプリ → アプリを作成**
3. ユースケースで **「Threads APIを利用する」** を選ぶ
4. アプリ名（例: `threads-ops-2`）と連絡先メールを入力して作成

### 権限を追加する

左メニュー **ユースケース → Threads APIにアクセス → アクセス許可と機能**

次の権限を **「+ 追加」** します（ステータスが「テスト準備完了」になればOK）。

```
threads_basic
threads_content_publish
threads_manage_insights
threads_read_replies
threads_manage_replies
threads_delete
threads_manage_mentions
```

`threads_location_tagging` と `threads_share_to_instagram` は不要です。

### コールバックURLについて

同じ画面の **設定** にコールバックURLの入力欄がありますが、**空のままで構いません**。
保存でエラーが出たら、キャンセルして先に進んでください。この手順では使いません。

---

## 2. 名義をテスターに登録する（名義ごと）

### 招待を送る

1. 左メニュー **アプリの役割 → 役割**
2. **メンバーを追加**
3. 一番下の **「Threadsテスター」** を選ぶ（「テスター」ではありません）
4. Threads のユーザー名を入力（`@` なし）して送信

### 招待を承認する

**Threads のスマホアプリ**で行います。

1. その名義に切り替える（プロフィール左上のアカウント名をタップ）
2. 右上 **≡ → 設定 → アカウント → ウェブサイトのアクセス許可**
3. **招待** タブ → アプリ名 → **承認**

> 名義は **公開アカウント** である必要があります（設定 → プライバシー → 非公開プロフィールをオフ）。

Meta 側の「アプリの役割」で **承認済み** になれば完了です。

---

## 3. アクセストークンを発行する（名義ごと）

**ここが一番間違えやすい箇所です。**

発行されるトークンは、**そのブラウザが `threads.com` にログインしている名義のもの**になります。
一覧で選んだ行の名義ではありません。

### 手順

1. **シークレットウィンドウ**（Ctrl+Shift+N）を開く
2. https://www.threads.com/ に **トークンを取りたい名義でログイン**
3. **同じウィンドウで** https://developers.facebook.com/ にログイン
4. 自分のアプリ → **ユースケース → Threads APIにアクセス → 設定**
5. 一番下の **ユーザートークン生成ツール** → **アクセストークンを生成**
6. ダイアログの見出しが **目的の名義になっているか確認**
7. 「理解しました」にチェック → **コピー**

> ダイアログを閉じると二度と表示されません。閉じる前にコピーしてください。

### よくあるエラー

| 表示 | 原因 |
| --- | --- |
| `The user has not accepted the invite to test the app.` | 手順2の承認が未完了、または `threads.com` に別の名義でログインしている |
| 別の名義の名前が出た | `threads.com` のログイン名義が違う。ログインし直す |

---

## 4. 管理画面に登録する

1. https://threads-ops-app.vercel.app/settings を開く
2. **「名義を追加」** の欄にトークンを貼り付ける
3. **名義を追加** をクリック

`@ユーザー名 を追加しました` と出れば完了です。持ち主はトークンから自動で判定されます。

> 登録直後は **停止中** です。投稿されることはありません。
> 準備が整ってから「停止中 → 稼働」に切り替えてください。

---

## 5. キャラ設定を自分で登録する

投稿文を作るには、名義ごとのキャラ設定が必要です。**管理画面から自分で登録できます。**

1. 左メニューの **キャラ設定** を開く
2. **「@名義 のキャラ設定を作る」** を押す
3. 各項目を埋めて **作成して名義に紐づける**

設定画面の Persona 欄にある **設定する** からも開けます。
一度作ったあとは、同じ画面の **編集** でいつでも直せます。

埋めるのは次の項目です。

```
地名:          （拠点にする土地。他の名義と被らないこと）
名前:          （読み仮名つき）
霊視歴:        （◯年。一度決めたら変えない）
視える範囲:    （◯ヶ月先〜◯年先。一度決めたら変えない）
世界観:        （その土地の由緒、語り口、避けたい空気感）
NGワード:      （絶対に言わないこと）
1日の投稿本数: （3〜5本など）
投稿する時間帯: （06:00〜23:55など）
誘導先:        （プロフィールのリンク / ピン止め / なし）
```

**地名は他の名義と被らないようにしてください。** 世界観が重なると、同じ運営者だと分かりやすくなります。

設定を変えても、すでに作られた投稿案は書き換わりません。次の生成（毎日15:30ごろ）から反映されます。

---

## 日々の運用

| 時刻 | やること |
| --- | --- |
| 毎日 15:30〜16:30 | 翌日ぶんの投稿案が自動で作られる（17時には揃っています） |
| **19:00 以降** | **管理画面の「投稿予定」で確認し、承認する** |
| 翌日 | 承認したものが予定時刻に自動投稿される |

**承認しなければ投稿されません。** 内容がおかしければ「却下」または「編集」してください。

コメントへの返信は自動です。「リプライ」画面で、除外された相手を確認できます。
除外がおかしいと思ったら「除外を取消」を押せば、次回返信されます。

## 困ったときは

| 症状 | 対処 |
| --- | --- |
| 名義が画面に出てこない | グループの設定が必要です。管理者に連絡してください |
| トークンの期限が近い（残り10日以下） | 自動で延長されます。失効した場合は手順3からやり直し |
| 投稿されない | その名義が「停止中」になっていないか確認 |
| 返信が送られない | 「自動返信」が OFF になっていないか確認 |

### 当たった投稿の骨格を使い回す（キャラ設定のチェック）

手動で当たっている形がある名義は、キャラ設定の「当たった投稿の骨格を使い回す」を ON にします。
ON にすると、その名義でコメントが多かった投稿を骨格として、行数・順番・言い回しをそのまま写して書きます。
変わるのは時刻や日付、置いてもらう合図（絵文字・合言葉）、季節の語だけです。
OFF のときは毎回ちがう形を作ります（型のガイドに沿って書く）。

### お客様の声（口コミ）を投稿に使う

リサーチのページの「お客様の声」に、鑑定を受けた方からもらった言葉を名義ごとに貼ります。
貼った声は、その名義の投稿にたまに1件ずつ「声を引く型」として混ざります（1件は1回だけ）。
投稿では一部を「」でそのまま引用し、要約や脚色はしません。名前や住まいなど、その人が分かる情報は伏せてから貼ってください。
画面写真しか無いときは文字に起こして貼ります。

### レポートの提案に返事をする

リサーチのページの「昨日のレポート」にある「指摘と提案」の各行に、「休む」「1本」「1本バズ」「2本」「そのまま」のボタンがあります。
押すと、その名義の明日ぶんの下書きを指示どおりに作り直します（30〜60秒）。前の下書きは却下になります。
「そのまま」は落ち込みの自動調整をせず、名義の設定どおりに作ります。
「休む」以外は文章を作り直すので、1回につき数円〜十数円の費用がかかります。

### 相談（ツールの中の Claude）

左のメニューの「相談」で、Claude に話しかけられます。会話は全員で共有され、誰の発言かが名前で分かります。
方針（CLAUDE.md と docs/claude-memory）、最新のレポート、名義の設定、監視リストを踏まえて答えます。
頼めばその場で反映もします。例:
- 「うたは明日1本にして」「うたは明日休み」 → その日の指示を保存し、下書きを作り直します
- 「うたに明日の朝7時に属人型を1本足して」 → 型と時刻を指定して作ります（承認待ちになります）
- 「星蘭の合言葉を求める本数を2にして」「雅のバズ狙いをOFF」 → キャラ設定を変えます（次の生成から）
- 「うたの明日の下書きを見せて」 → 一覧を出します
- 「星蘭は明日、属人型2本とバズ型1本で作り直して。バズは合図🙏で暦は使わない」 → 型と本数と内容の指示を付けて作り直します
- 「うたの明日 23:47 の本文をこれに差し替えて（本文を貼る）」 → 本文をそのまま入れ替えます
運用に関わることは誰でも頼めます。相談からできないのはツールの仕様（コード）を変えることだけです。
実行した内容は「実行」として会話に残ります。1回の返事に数円〜十数円、作り直しはさらに数円〜十数円かかります。

### 明日への指示（費用のかからない相談）

リサーチのページの「明日への指示」に、レポートを読んで決めたことを書いておくと、15:30 の生成がそれを読んで作ります。
名義ごとに「構成（バズ1本＋属人1本、など）」と「指示の文章」を渡せます。全名義に共通の指示も書けます。誰が書いたかも残ります。
これは生成に同梱されるので、相談のような1回ごとの費用はかかりません。
作ったあとに直したいときは、Claude Code から「うたの 23:47 の本文を差し替えて」「属人型を1本足して」のように頼みます。

### 投稿を Threads から消す

投稿予定の「投稿済み」の各行に「Threads から削除」があります。押すと確認が出て、Threads 上の投稿が消えます。戻せません。
費用はかかりません（Claude は使わず、Threads の API を呼ぶだけ）。記録は「削除済み」として残ります。
Claude Code からは「うたの今日 21:42 の投稿を消して」と頼めます。

### 伸びなかったバズ型の自動削除

バズ型の投稿は、投稿から24時間たっても「いいね0・コメント0」なら自動で Threads から消します（5分おきの処理で判定）。
属人型・霊視開始型・除外フック型は資産なので消しません。名義ごとにキャラ設定の「伸びなかったバズ型を自動で消す」で OFF にできます。
消した記録は投稿予定に「削除済み」として残ります。

### 土地移動型（属人系）

「本日は◯◯県にいます…『◯◯』とだけ残してください」の型です。その土地に縁のある人に刺さり、バズらなくても人が来ます。
「明日への指示」の構成に「土地移動1」と書くか、Claude Code で「うたに明日、土地移動型を1本足して」と頼めます。
県名は名義の土地の近くで、直近に使ったものは避けます。合図は県名です。

### 「稼働／停止」と「自動返信」の関係

- 停止中: 投稿の生成と自動投稿を止めます。手で出した投稿へのコメントは、自動返信が ON なら取り込んで返します。
- 自動返信 OFF: 返信を送りません（コメントの取り込みと表示はします）。
- 「投稿は手で、返信は自動」にしたいときは、停止中＋自動返信 ON にします。

### 1日の本数と構成の関係

1日の本数は全名義「2〜5本」で、日ごとにその中で決まります（落ち込み中は絞る）。キャラ設定の「構成の要望」（例: バズ＋属人）は本数を固定せず、型の比率として繰り返します。3本の日なら バズ・バズ・属人、4本なら バズ・バズ・属人・属人 のように繰り返し、どの型をどの時間帯に置くかは日ごとにランダムです（早朝はバズ、深夜は属人、という固定はしません）。投稿できる時間帯は 0時〜24時です。

### 投稿ごとの切り替え（前の1本の結果で次の1本の型を決める）

15:30 に作った 1日ぶんはそのままにし、各投稿の 2時間前に「直前の投稿の 3時間後の判定」と見比べます。表は次のとおりで、型の段（超バズ／バズ／属人）が違うときだけ、その 1本を同じ時刻で作り直します。同じ段なら何もしません。
- 悪い（300未満）→ 超バズ特化（超バズを使わない名義はバズ特化。画像ストックが無いときもバズ特化）
- 普通（300〜1,000）→ バズ特化
- 良い・バズ（1,000以上）→ 属人（属人で 1,000 ならバズ扱いで属人のまま）
作り直した 1本は承認待ちに入り、見なければ投稿時刻に自動で承認されます。作り直しで超バズ特化型になった投稿は、系統の画像が無くてもストックのどれかを付けるので、人が気づかなくても出ます（作り直しで土地移動型・寺社訪問型になることはありません）。
投稿に人が付けた画像は、その名義のストックにも自動で残ります（系統は土地名か、生成が求めていた系統。土地移動型・寺社訪問型で付けたものは「場所が分かる画像」）。次に同じ土地の投稿が出たときの案内に「ストックにあります」と出ます。
元の投稿は「却下」になり、理由に切り替えの内容が残ります。超バズ特化だけの名義（雅）と、キャラ設定で `perPostSwitch=false` にした名義には当てません。

### 表示数の「1時間後・3時間後」と良い・悪い

投稿の 1時間後と 3時間後に表示数を取り、3時間後の数字で良い・悪いを付けます（手で出した投稿も対象）。線は全名義共通の絶対値で、フォロワー数や名義の平均とは比べません。
- 300未満 = 悪い（配信に乗っていない）／300〜1,000 = 普通／1,000〜3,000 = 良い／3,000以上 = バズ。1時間後に 3,000 を超えたらその時点でバズ。
- 投稿一覧の投稿済みと、リサーチのレポートの投稿表に「1h」「3h」「判定」が出ます。翌朝 03:20 の取り直しで最終の表示数も残ります。
- 「悪い」が 3本続いた名義は抑制中と見て、生成のときに本数を絞ります。
- 線を変えるときは `npm run ops -- lines --bad 300 --good 1000 --buzz 3000`（引数なしで今の線を見る）。相談からも変えられます。
- 2日つづけて「その日の最高の 3時間後の表示」が 1,000 に届かなかった名義は、翌日の生成でバズ特化の枠を超バズ特化型に替えます（キャラ設定の「超バズ特化型を使わない」が付いている名義は除く。日数は `superBuzzAfterDays` で変えられ、0 で止められます）。
- 3日つづけて「その日の最高の表示」が 300 に届かない名義は、その日の生成を超バズ特化型だけにします（雅と同じ扱い。`superBuzzOnlyAfterDays` で日数を変えられ、0 で止められます）。300 を超える日が出れば通常の構成に戻ります。集客が来ている名義（直近 30日に LINE 追加がある、または 1,000 以上の投稿がある、またはキャラ設定で `hasAudience=true`）には当てません。そういう名義が落ちたときは 3本以上にして、超バズ 1本＋属人＋バズ特化を全部入れます。

### 手で投稿したものへの自動返信

名義を一時停止にして自動返信だけ ON にすると、「投稿は手で、返信は自動」になります。手で出した投稿も、15分に1回の取得のときに Threads から直近の投稿を読み直して対象に入れるので、コメントは最長でも 15分ほどで拾われ、次の 5分の送信で返信されます。

### 画像ストック

左のメニューの「画像ストック」に、バズ型の画像投稿に使う画像を系統（ジャンル）ごとに貯めておきます。
- 種類は「1枚」（いいねと🍀で運氣が上がります、の型）と「2枚」（2本の指でくっつけてみて、の型。1枚の景色を左右に割った2枚を左・右の順で）。
- 系統は自由な語（朝日、龍、鳥居、海、花 など）。同じ語でそろえると、生成のときに系統で選べます。
- 「全名義で使う」か、特定の名義だけかを選べます。
生成のとき、「画像バズ型」の枠には、ストックから画像を自動で添えます。選ぶ順は、AI が選んだ系統（漢字なら字）→ 本文や合図の被写体（⛩️なら鳥居、🐉なら龍、🌙なら月）に合う系統 → 縁起物（系統が「開運」「縁起」のもの）→ その名義でいちばん使っていないもの。系統は画像の種類（水墨画など）で書いて構いません。画像バズ型は届いていない名義の露出づくり用で、構成に「画像バズ2」のように書いて使います。
合う画像が無いときは「画像が未準備」の保留になり、画像を付けると承認待ちに戻ります。使い回しは構いません。
画像はファイル選択のほか、枠にドラッグして落としても登録できます。同じ系統なら何枚でもまとめて入れられます（1枚の型は 1枚＝1件、2枚の型は 1枚ずつ左右に割って 1件。割ってある 2枚を組にするときは、その印を付けて偶数枚を左・右の順で）。選んだ画像は一覧に並び、1件ずつ説明を書けます（書かなかった件には「まとめてのメモ」が入ります）。説明は生成のときに画像を選ぶ手がかりになるので、場所や中身を書いておきます。
「場所が分かる画像」の印: 鳥居・富士山・寺社のように場所が特定できる画像は、自動では超バズ特化型だけに使います（系統の語から自動で印が付き、あとから直せます）。
土地移動型・寺社訪問型（「今、大阪に来ています」）の投稿は、自動では画像を付けません。投稿の欄に「大阪の画像を入れてください（住吉大社、大阪天満宮、難波神社など、大阪と分かる寺社や名所）」と案内が出て、「画像が未準備」の保留になります。承認のときに、これまで通り人がその土地の画像を付けると承認待ちに戻ります。ストックの系統か説明に「大阪府 住吉大社」のように土地の名前が入った画像があれば、案内に「画像ストックにあります」と出ます。
バズ特化型・霊視開始型の枠にも、印の無い「1枚」の画像を添えます。使いすぎないように「直前の投稿に画像が付いていたら次は付けない」を繰り返します（超バズ特化型の次のバズ特化型は画像なし）。属人型にはストックの画像を付けません（土地移動型・寺社訪問型は人が付ける土地の画像だけ）。基本は全名義で使えるものとして貯め、名義専用に保存したものがあればそれを先に使います。ストックに入れていない画像は使われません。
漢字の 2枚（福、縁、運 など）は、説明にその字を書いておきます。生成 AI は在庫の字から 1つ選び、本文をその字の意味に合わせて書きます（縁なら「途切れていたご縁が、また結ばれます」）。字そのものは本文に出さず、くっつけて初めて分かる形です。
一覧は「2枚／1枚」→「名義」→「系統」の順に分かれています。各画像の「編集」を開くと、系統・メモ・使う名義をあとから直せます（画像そのものは変えられないので、差し替えるときは「外す」→登録し直し）。

### 画像ストックを別の環境へ持っていく

`npm run stock:export` で `./stock-export/` に画像と一覧（manifest.json）が書き出されます。フォルダごと相手の環境に置いて `npm run stock:import -- --from ./stock-export` を実行すると、画像がその環境のバケットに保存され、系統・説明・種類・場所の印つきでストックに登録されます。同じ画像は飛ばすので、何度実行しても増えません。名義指定は @ユーザー名で照合し、相手に無い名義は「全名義で使う」になります。
