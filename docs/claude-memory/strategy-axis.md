占いアカウント運用の最大の軸は **「この人だからこそ頼りたい」と思わせること**（2026-09-03 に本人が明言）。

- 手法: SNS なので**不安を示してから、肯定で受け止める**。煽って終わらない。エンタメに寄せると「バズ狙い」が透けて刺さらない
- CTA: **コメントは求める。求めすぎない。いいねだけを求めない**
- バズればいいという話ではない。**世界観（一貫した人物像）**が集客を決める
- 「多少言い回しが一緒なのは仕方ない」— 表面の語彙の重複は問題視していない。問題は世界観の有無

**Why:** 表示数・いいねを最大化すると届く層が薄くなり、LINE 登録につながらない（641コメント→21登録、いいねだけの投稿は登録が悪いと実体験済み）。

**How to apply:** 生成の SYSTEM とレポートの判断軸に入れてある（lib/server/generate.mjs / report.mjs）。属人型の指示は星蘭で当たっているので**触らない**。「数字の権威をやめる／繰り返しの反転／CTA変更」の提案は取り下げ済み。関連: [[evaluation-proxy]] [[account-directions]]

**合言葉を求める本数は1日2〜3本**（本人 9/7）。前日が2本なら3本、3本なら2本と交互。残りの投稿は「霊視に入ります」「お声をくだされば」のように置きたい人が置ける終わり方にする。ツールでは名義の「合言葉を求める本数」（persona.askPerDay = "2-3"）。**全名義に設定済み（9/7、本人「全アカウント同じがいい。コメントを求めすぎ」）。星蘭・玲月・teamB も含む。** これは「星蘭は触らない」の例外で、本人が明示した。

**本数の運用ルール（本人 9/7）**: Threads は特性上バズと落ち込みを繰り返す。**落ち込んだら1日1本に減らす。しない日があってもよい。** 良い感じでも**1日3〜4本を徹底、いいからといって増やさない。** 1日の構成の型はランダムに使うが、必ず使う必要はなく、星蘭のように当たっている名義は本来したい投稿でよい。**星蘭は試験的に「明確にバズ狙い」を1日1本入れて、その後どうなるかを見る**（persona.buzzTrial）。うたは 9/5 から全投稿が100表示未満（9/3 に1.4万出た文面の写しでも61）＝落ち込み。ツールでは lib/server/slump.mjs が直近の表示数中央値と基準の中央値を比べて判定する。

**落ち込み中の1本はバズ型**（本人 9/7「落ち込んでいるときは、バズ狙いを1日1本だけとかでもいい」）。persona.slumpBuzz（既定 ON）。露出が無い名義に1日1本バズ型を混ぜる案（うた・雅・teamB 4名義）は提案済みで、本人の返事はまだ。露出が止まると LINE 追加はゼロになる（9/6 全名義未入力ではなく実際に無い）。

**合言葉は単純に、改行は少なく**（本人 9/8「置かれたコメントが複雑すぎ」「改行が多すぎ」）。合言葉は絵文字1つか2文字以内の身近な語（🙏🌿🌱、縁・恋・水・貴船）。烏帽子岩・舟形石・梶の葉のような固有名詞は禁止。改行は意味の切れ目だけ、空行は本文全体で2つまで。生成の共通指示に入れ済み。

**飾りの強調は絶対NG**（本人 9/8）: 「✴︎✴︎【 祈り 】✴︎✴︎」のように、AI が強調に使う絵文字（✴︎ ✳️ ★☆）やアスタリスク（* ＊ **）で語を囲むのは絶対に禁止。【】「」で囲うのは OK。投稿・返信の両方。ツールでは生成指示に入れ、保存前に取り除く処理も入れた。

**お客様の声（口コミ）を使った投稿はたまに OK**（本人 9/8）。リサーチのページに「お客様の声」欄を作り、名義ごとに貼る。1件は1回だけ、「声の日」の構成か4日に1回ほど1本だけ混ぜる。一部を「」でそのまま引用、要約・脚色・前置き禁止、相手が分かる情報は書かない、自慢の形にしない。落ち込み中は使わない。画面写真はチャットで私が文字起こしできる。

**落ち込み中は属人型を打つ意味がない。バズ型で露出を戻してから属人型**（本人 9/11 の観察: 9/10 夜のバズ型 159いいね/98コメのあと、9/11 朝の属人型が伸びた）。運用者はこの種の指示をツール内の「相談」（/chat）から出して反映する（suzuki も同様）。

**反応ゼロのバズ型は消す**（本人 9/11）: バズ型は24時間で いいね0・コメント0 なら自動削除（lib/server/auto-delete.mjs、persona.autoDeleteFlops 既定ON）。属人型は資産なので残す。削除はThreads APIのみで費用なし。

**同じ文面・同じ画像の使い回しは OK**（本人 9/11）。「文言は使い回さないとおかしくなる」。重複を止める仕組みは入れない（一度入れて取り消した）。画像は名義をまたいでも使ってよい（teamB は同一人物設定）。私の早とちりで作った重複チェックは取り消し済み。質問には質問として答え、頼まれていない仕組みを足さない。

**数は 0〜9 の数字で**（本人 9/12）: 時刻・分・年数・回数は「3時15分」「27分後」「15年」。漢数字は「千年」「万年」「一粒万倍日」「お一人お一人」のような言い回しだけ。生成指示＋保存前の自動変換（text-clean.mjs normalizeNumbers）。

## 型の線引き（本人 9/12。この3段で考える）

| 段 | ツールの型 | 使う名義 |
| --- | --- | --- |
| 超バズ特化型 | image_buzz（画像が主役、本文1〜4行、画像ストックから自動） | 雑魚の名義だけ（雅）。属人型で回している名義は本当に伸びなくなったときだけ |
| バズ特化型 | buzz_engagement（朝なので言いますが…、日付と時刻を積む型）。霊視開始型もこちら側 | うた、星蘭、玲月など |

## 名義の段階（本人 9/12。運用の基本の考え方）

1. **いちばんきれいなのは属人型だけ**で回すこと。
2. 落ち込みを想定して、**バズ特化型を入れつつ属人型で集客**する。うたのように一度上がった名義はここまで。超バズ特化型は要らない。バズ特化型で立て直して属人型に戻す。
3. **弱すぎる名義は属人型を打っても意味がない**ので、**超バズ特化型も織り交ぜる**（玲月、雅）。
- 星蘭は超バズ特化型は不要（バズ特化1本＋属人1本）。
- バズ特化型の分かりやすい見本は @mikoto_uranaishi（5,631人。早朝の暦型を毎日）。
- 超バズ特化型のお手本は超バズ特化型の枠にしか渡らない。うた・星蘭の生成には混ざらない。

**段階の判定をレポートに**（本人 9/12）: 落ちて戻る気配なし→「超バズ特化を挟みますか」／超バズで3日コンスタント（1本あたり300以上、最大/最小5倍未満）→「超バズ＋バズ特化に切り替えますか」／超バズ＋バズ特化で安定→「属人を1本入れますか」／1回当たっただけ（最大1000以上・最小300未満）→「属人はまだ」。属人型の投稿は貴重。lib/server/stage.mjs。判定は機械、決めるのは本人。
