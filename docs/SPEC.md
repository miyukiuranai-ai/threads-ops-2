# threads-ops 仕様書（同じものをもう1つ作るための設計書）

この文書は、いま動いている Threads 自動運用ツールを、別の環境に「全く同じもの」として作り直すための仕様です。
読み手は Claude Code です。ここに書いてある動きをそのまま実装してください。
本家との違いは1点だけ、**画面の色を緑から黒にする**ことです（末尾の「配色」）。
**9/13〜9/14 に足した仕様は末尾の「14. 追補」にある。4〜7 章と食い違うところは追補が正しい。**

いちばん確実なやり方は、この文書を渡したうえで本家のリポジトリを丸ごと取り込み（clone）、
環境変数と配色だけを差し替えることです。ゼロから書く場合は、この文書の順に作ってください。

---

## 0. 目的と前提

- Threads の複数名義（アカウント）を、**Threads 公式 API だけ**で自動運用する。ブラウザの自動操作はしない。
- 投稿文は Anthropic API（Claude）で生成し、人が承認してから投稿する。承認が無ければ締切で自動仕分けする。
- 目的は LINE の友だち追加。反響（表示・いいね）ではなく登録で判断する。
- 分離して建てる理由: 名義数を増やしたときの弊害を、いまの運用に影響させずに試すため。**本家と Firestore・ストレージ・Vercel・定期実行を共有しない。**

## 4. 投稿の型（POST_TYPES）

| キー | 名前 | 骨格 |
| --- | --- | --- |
| `attract_intro` | 属人型 | 冒頭2行で読者を絞る → 地名・肩書き（年数）・名乗り → 秘匿の告白 → 能力を数字で → 近い未来と遠い未来の比喩 → 第三者の声 → 合言葉で締め。別の書き方として「物語型」（挫折や転機、誰かの言葉。締めはフォロー＋生年月日）。最後に名前だけの署名も可。固定の比喩はぶれさせない |
| `travel_note` | 土地移動型（属人系） | 「本日は◯◯県にいます」→ 氣の流れが変わった → 止まっていたものが動き始める方が何人か → ご縁か仕事かは追っていない → 県名を置いてもらう → 少し視てみます。県名は名義の土地の近く、直近と重ねない。名乗り・暦なし。10〜12行 |
| `exclusion_hook` | 除外フック型 | 1行目で対象外を宣言して弾く → 地名や経歴は出さない → 断定 → 合言葉で締め |
| `reading_open` | 霊視開始型 | 時刻の宣言 → 本名不要 → 1人1人深く向き合うので真剣な人だけ → 合図ひとつ（絵文字か恋・仕事・人から選ばせる。生年月日も可）→ 受付時間 → 静かに締め。8〜10行、名乗りなし。落ち込み中のブーストにも使う |
| `buzz_engagement` | バズ型 | 日付・時刻・偶然性を1行目 → 「いいねできた人だけ」の条件 → 良いことを断定 → 即時性の数字 → いいねを軸、コメントは一語だけ → 3〜5行。変種: 早朝5〜9時の暦を積む型、「◯月◯日、流れが変わる方が何人か。好きな動物を置いて」、「朝なので言いますが、涙を流しながら腰を抜かすほどの良いことが」。画像を添えてよい。`buzzTone=light` の名義は煽りと数字の断定を使わない |

## 5. 生成の共通ルール（SYSTEM。文言はこのまま）

- 最大の軸「この人だからこそ頼りたい」。不安を言葉にしてから肯定で受け止める。面白がらせるより信用させる。コメントは求めるが求めすぎない。いいねだけを求めない（バズ型を除く）。
- 参考投稿からは構造だけを借り、語彙・言い回し・比喩は借りない。Persona の世界観・一人称・語尾を最優先。過去投稿と同じ書き出し、同じ比喩を繰り返さない。
  - 骨格を使い回す名義（reuseWinners）ではこの3行を差し替える: 骨格の行数・順番・言い回しをそのまま写す。変えてよいのは時刻・日付・合図・季節の語だけ。時刻は枠に合わせる。長さは骨格に合わせ、1日1本は短い骨格（6行以内）。長い名乗り型は1日1本まで。
- 合言葉は「置く人が迷わず打てるもの」: 絵文字1つ、または誰でも読める2文字以内の身近な語（縁、恋、水、光、朝、月、花、鈴、名義の土地名）。難しい地名・固有名詞・読めない漢字・3文字以上は禁止。土地移動型の合図は県名でよい。「好きな絵文字をひとつ」「好きな動物」も可。直近12本の合言葉は避ける（絵文字と土地名は数日空けば可）。
- 暦は「対象日の暦」に書かれた名前だけ。無い名前や縁起を作らない。
- 誇大な断定（必ず儲かる、病気が治る）や医療・投資の助言はしない。
- 本文 500 文字以内。1行に1〜2文。改行は意味の切れ目だけ。空行は段落の切れ目に1つ、本文全体で2つまで。骨格を写すときは骨格の行数と空行を守る。
- 数は 0〜9 の数字（3時15分、27分後、15年、2〜3ヶ月先）。漢数字は「千年」「万年」「一粒万倍日」「お一人お一人」のような言い回しだけ。
- ハッシュタグなし、URL なし。絵文字は行末に1つまで。
- **アスタリスク（* ＊）や ✴︎ ✳️ ❇️ で語を囲む強調は絶対禁止。太字の記法も禁止。【】「」で囲うのは可。**
- slotName は型が分かる短い英小文字スネークケース。
- imageBrief は画像方針に従う（always/sometimes/rarely）。本文と矛盾しない、土地に実在しうる情景、構図と被写体を1〜2文。imageRequired は本文が画像そのものを指すときだけ true。迷ったら false。
- 出力は JSON のみ: `{"posts":[{"slot","type","slotName","body","keyword","imageBrief","imageRequired","intent"}]}`。

プロンプト（user）に渡すもの: Persona（名前・人物設定・文体ルール・禁止表現）、使う型のガイド、投稿枠（時刻と型。骨格を写す名義では枠ごとの扱いを注記）、参考投稿（型ごとのお手本。`usage` があれば「使いどころ」として添える）、骨格（reuseWinners のとき最大24本、期間が長ければ均等に間引く）、直近の自投稿（8本）、合言葉を求める本数（askCount。残りは合言葉を指定しない。「合言葉を指定しない締め方の手本」＝usage が「求めない」で始まるお手本を型に関わらず渡す）、対象日の暦（「暦の日」の構成のときだけ）、1日の構成（役割の並び）、いただいた声（口コミ型の枠）、運用者からの指示（最優先）、使用済みの合言葉、直近の結果から分かっていること（レポートの続ける・やめる）。

生成後の後処理: 飾り記号の除去（text-clean）、数字の統一、合言葉の本数超過分を空にする、ジッターは本文を書く前にかける（本文の時刻と予定時刻を一致させる）。

## 6. 1日の組み立て（pipeline.generateForAccount）

1. 名義の Persona を読む。その日の指示（directives）と全名義共通の指示を読む。
2. 落ち込み判定（slump）: 2〜21日前の投稿の表示数の中央値を基準、16時間以上たった直近3本の中央値が基準の15%未満で「落ち込み」（基準は300以上、4本以上あるとき）。
3. 本数の決定: 指示（rest=0 / one=1 / one_buzz=1 / two=2 / keep=設定どおり / mix=types の数）＞ dayMix の数 ＞ 落ち込み中は slumpPosts（既定1、4回に1回は休む）＞ postsPerDay。
4. 枠の決定: bands から出現率で帯を選び、最短の間隔を満たすように帯の中でランダムに置く（40回引き直し、だめなら前から詰める）。24:00 は 23:50 扱い。日付をまたぐ帯は 25:10 のように表す。ジッター ±3〜10分をここでかける。
5. 型の割り当て: 帯の型 → dayTypes の順。dayMix / mix があれば並び順（バズ型は早い枠、霊視開始→除外→土地移動→属人型は遅い枠）。落ち込み中は全部ブーストの型（2本以上なら1本目バズ型）。buzzTrial は最後の枠以外の1枠をバズ型。手で型を指定した生成（--types）はこれらで上書きしない。
6. 1日の構成の型（useDayPatterns、dayMix が無いとき）: 名乗りは深夜／名乗りは朝／暦の日（名のある暦がある日だけ）／静かな日／短い日／弾く日／声の日（未使用の口コミがあるとき）。前の2日と違うものを選ぶ。暦の日は60%で優先。
7. 合言葉を求める本数: askPerDay の範囲で、前日の本数と交互。
8. 材料: お手本（型で絞る。無ければ全部）、骨格（期間 or コメント数順）、直近8本、使用済み合言葉（直近12本）、レポートの続ける・やめる（直近3日）、暦（travel/calendar 用）、口コミ（4日に1回ほど、2本目の枠）。
9. Claude に生成させ、後処理し、`posts` に `pending` で保存。口コミを使ったら usedAt。

## 7. 定期実行

| 経路 | 時刻 | 内容 |
| --- | --- | --- |
| `/api/cron/generate`（Vercel Cron `30 6 * * *` = 15:30 JST） | 毎日 | 前日のレポート生成 → 翌日ぶんの投稿生成（全名義を並列、作成済みの名義は飛ばす）→ 古い runs の削除 |
| `/api/cron/refresh-tokens`（Vercel Cron `0 21 * * *`） | 毎日 | 失効まで少ないトークンを延長。10日前から警告 |
| `/api/cron/publish` | 5分おき（外部から） | 承認済みで予定時刻を過ぎた投稿を送る（20分以上遅れは missed）。本文先頭の時刻を実際の時刻に書き直す。画像・動画は署名付き URL でコンテナを作り、FINISHED まで1分ごとに最大5分待つ。相乗り: 23:30 の自動仕分け、03:20 の反応取り込み、24時間で反応0のバズ型の自動削除 |
| `/api/cron/replies` | 5分おき（外部から） | コメントの取り込み → 判定 → 送信 |

外部の5分おきは Google Apps Script の時間トリガー（`UrlFetchApp.fetch(url + '?key=' + CRON_SECRET)`）で叩く。GitHub Actions の例は `docs/github-actions-publish.yml.example`。Vercel Cron は 34 分ほど遅れることがある。

### 7-2. 自動仕分け（23:30）

承認待ちのうち: 本文が画像を指しているのに素材が無い → 却下。予定時刻を20分以上過ぎた → 却下。それ以外の文章だけの投稿 → 承認。`autoReviewExempt` の名義は対象外。

### 7-3. 返信（replies / send-replies）

- 取り込み: 直近72時間の自分の投稿に付いたコメント（`media_type` も保存）。3文字以下は合言葉だけ（category keyword）、それ以上は message。
- 判定: message は Claude で normal / negative / spam に分類。negative（否定・冷やかし・挑発）と spam は skipped。冷やかし・宣伝と判定した人の同じ名義への別コメントも skipped。**本文が空、画像・動画だけのコメントも skipped。** 被り（同じ人が既定2名義以上、teamB は4名義以上に出現）も skipped。それ以外は queued。
- 送信: コメントから5〜30分遅らせる。連続送信は20〜60秒のランダム間隔。深夜2〜6時は送らず、朝に「遅延謝罪」のテンプレートで返す。1回の実行で送るのは少数。テンプレートは名義専用があれば共通より優先し、直近に使ったものを避ける。飾り記号と数字の統一を通す。
- 返信の型（本人の実績）: 「LuLu 様、このたびはご連絡いただきありがとうございます。鑑定文が2000文字を超えてまいりますので、プロフィールのリンクよりご連絡いただけますでしょうか」で LINE へ。

### 7-4. 反応の取り込み（03:20）と評価

- 各投稿の insights（views, likes, replies, reposts, quotes, shares）を `history` に保存。
- 評価の物差し: 表示数の中央値（平均は使わない）。取れ高＝LINE 追加数 ÷ 表示 × 1万（登録率と表示数の相関は出さない）。コメントが付いていいねも一定ある投稿を良しとし、いいねだけの投稿は評価しない。

### 7-5. 日次レポート（15:30、対象は前日）

Claude に渡す: 名義ごとの前日の各投稿（時刻・表示・いいね・コメント・本文）、直近7日の推移（本数／1本あたりの表示の中央値）、落ち込み判定、いまの要望の構成、LINE 追加数と取れ高。
返す JSON: `overall`、`alerts[{account, level(落ち込み|注意|好調), message, proposal}]`（提案は問いの形。「落ちた→バズ→回復」は未検証と明記）、`accounts[{keep[], stop[], note}]`。母数が少なければ「まだ分からない」。
画面ではレポートの各指摘の下に返事ボタン（休む／1本／1本バズ／2本／そのまま）を出し、押すと `/api/directive` が指示を保存して翌日ぶんを作り直す。続ける・やめるは翌日の生成に渡す。

### 14-1. 投稿の型は 8つ（POST_TYPES の全文）

4 章の 5つに 3つ足して 8つ。段は「超バズ特化／バズ特化／属人」の 3段で考える。生成に渡す型ガイドの文言はこのまま。

| 段 | キー | 名前 | 目的 |
| --- | --- | --- | --- |
| 超バズ特化 | `image_buzz` | 超バズ特化型（画像） | バズ型のさらにバズ特化。画像が主役で本文は 1〜4行。届いていない名義の露出づくり |
| バズ特化 | `buzz_engagement` | バズ特化型 | リーチ確保。アカウントの加速用 |
| バズ特化 | `reading_open` | 霊視開始型（バズ系） | コメントを集める。時刻を宣言して「今から視る」 |
| 属人 | `attract_intro` | 属人型（名乗り・由来） | 集客。地域と人物を出し、読み切った人だけを残す |
| 属人 | `personal_note` | 属人・素の型 | 集客。名義の土地と人物が主語で、仕掛けを使わない |
| 属人 | `shrine_visit` | 寺社訪問型（県内） | 集客。名義の県の中の寺社に「来ています」 |
| 属人 | `travel_note` | 土地移動型（県外） | 集客。「本日は◯◯県にいます」で土地に縁のある人を呼ぶ |
| 属人 | `exclusion_hook` | 不安煽り型 | 集客。読み手の不安を先に言葉にして、受け止める。弾くのが目的ではない |

**image_buzz（超バズ特化型・画像）のガイド**
- 画像ストックの在庫から imageGenre と imageKind（pair＝左右2枚のくっつけ／single＝1枚）を必ず選ぶ。imageRequired は true
- 漢字の2枚は、左右に割れた1文字（福、縁、運、叶 など）が、指でくっつけると1つの字として現れる仕掛け。使うときは在庫の字から1つ選んで imageNote にその字を書き、本文はその字の意味に沿った一言にする（縁なら「途切れていたご縁が、また結ばれます」、財なら「お金の流れが、静かに戻ってきます」）。字そのものは本文に書かず、くっつけて初めて分かるようにする
- 2枚（くっつけ）の本文: 1行目「2本の指でくっつけてみて✨」。2行目に良いことを一言（開運が、太陽のようにどっと降り注ぎます🌞）。または合図ひとつ（「⛩️」をおいた人から、聖域の力をお借りして視ていきます／そっと『🐍』を置けたら幸運のパワーを受け取り完了、更にいいねすると邪気退散）
- 1枚の本文: 「いいねと🍀で「運氣」上がります」のように1〜2行。いいねと絵文字ひとつで完結させる
- 字間を空けた表記（い い ね と 🍀 で「 運 氣 」上 が り ま す）を使ってよい
- 名乗り・経歴・暦・長い説明は入れない。1〜4行
- 合図を求めるなら絵文字ひとつ。求めなくてもよい（いいねだけの投稿として成立させてよい）

**buzz_engagement（バズ特化型）のガイド**
- 日付・時刻・偶然性のいずれかを1行目に置く（例: 9月3日に、いま素通りしなかった方）
- 「いいねできた人だけ」「これを見た人だけ」と、いいねを条件に組み込む
- 良いことが起きると断定する。ぼかさない（お金の不安がほどける、悪縁が消える、など）
- 即時性を数字で出す（早い方で22分後、15分以内に、など）
- 求める行動は「いいね」を軸にする。コメントを求めるなら一語だけ、軽く添える程度にする
- 短く保つ。3〜5行。字間を空けた表記を使ってよい
- 画像を添える形も選んでよい。添えるなら imageBrief に具体に書き、本文が画像そのものを指すときだけ imageRequired を true
- 次の形も選べる: ①早朝5〜9時に「時刻→まさか起きている方→今日の暦→短い時間帯だけ→合図ひとつ」（暦は「対象日の暦」にあるときだけ） ②「◯月◯日。このあたりで流れが変わる方が何人か視えています。全員ではないです。自分がそうなのか気になる方は、好きな動物（好きな絵文字）を置いて」 ③「朝なので言いますが、本日、涙を流しながら腰を抜かすほどの良いことが起きます。大丈夫。合図ひとつ」
- `buzzTone=light` の名義は煽りと数字の断定を使わない。挨拶、短い肯定、好きな絵文字を置いてもらう形

**reading_open（霊視開始型）のガイド**
- 1行目は時刻の宣言（例: 15:30になりました。無料霊視に入ります。／夜の9時。こんな時間にここに導かれた人、少しだけ視ます）
- 本名は不要、と一言。1人1人に深く向き合うので、真剣に自分と向き合いたい人だけ、と絞る
- 合図はひとつ。【🐍】【🙏】のような絵文字か、「恋・仕事・人」から一つ選ばせる。生年月日を添えてもらってもよい
- 受け付ける時間帯を書いてもよい（21:00〜24:00まで、など。枠の時刻から3時間ほど）
- 締めは「必要な方だけ、お待ちしております」のように静かに。煽らない。8〜10行。名乗りや経歴は入れない

**attract_intro（属人型・名乗り）のガイド**
- 冒頭2行で読者を絞る。全員に向けて書かない
- 地名 → 肩書き（年数） → 名乗り（読み仮名）の順で名乗る
- 「怖がられると思い、近しい人にしか話していなかった」という秘匿の告白を入れる
- 能力を数字で具体化する（何ヶ月先から何年先まで、など）
- 近い未来と遠い未来の見え方の差を、その人固有の比喩で表現する
- 第三者の声を短く引用する
- 最後に合言葉をコメントに置くよう促す。「優先します」で限定感を出す
- 別の書き方として「物語型」がある。挫折や転機、誰かの言葉で、なぜ視るのかを語る。締めは「しんどい人はフォローだけ置いて。生年月日を書ける人は書いて」のように軽く。Personaに書かれた来歴の範囲で書き、作り話を足さない
- 本文の最後に名前だけを一行置いて締めてもよい（署名）。名義の世界観にある比喩は毎回同じものを使い、ぶれさせない

**personal_note（属人・素の型）のガイド**
- お手本の骨格をそのまま使う。名乗りつきの短い自己開示、時刻を告げて霊視に入る、覚悟を問う、読み手の恨みを代弁して受け止める、など
- 土地と名前は必ず名義のもの。年数や視える範囲を語るなら人物設定にある数字だけ
- 合図はひとつ。土地名か絵文字。求めない締め（お声をくだされば）でもよい
- 不安を言葉にしてから受け止める。煽らない。8〜16行

**shrine_visit（寺社訪問型・県内）のガイド**
- 骨格は土地移動型と同じ。違いは場所が名義の県の中であること
- 1行目は「◯◯県◯◯寺におります」「今、◯◯市◯◯の麓におります」。寺社や場所は名義の県の中にある実在のもの
- 「今、少し氣の流れが変わりました」と変化を一言 →「特に今日は、長く止まっていたことが動き出す方が何人か強く入ってきます」→「ご縁なのか、仕事なのか。そこまではまだ追っていません」
- 合図は県名か市名。「妙に気になった方は『◯◯』とだけ残してください。今夜、少し視ます」
- 名乗り・経歴・暦は入れない。9〜11行。同じ文面を絵文字や語尾だけ変えて使い回してよい
- この投稿には運用者がその土地の画像を付ける。imagePlace に「都道府県 画像に向く寺社や名所を2〜3個」を書く

**travel_note（土地移動型・県外）のガイド**
- 1行目は「本日は◯◯県にいます」「今、◯◯県に来ています」。県名は名義の土地の近くで、行っていそうな場所。同じ県を短い期間に繰り返さない
- 「朝から少し氣の流れが変わりました」「私の勘は当たります」のような、その土地で感じた変化を一言
- 「特に今日、止まっていたものが動き始める方が何人か強く入ってきます」→「ご縁なのか、お仕事なのか。そこまではまだ追っておりません」
- 合図はその県名。「なぜか今、この投稿が気になった方は『◯◯』とだけ残してください」
- 締めは「これより、少し視てみます」のように短く。10〜12行。名乗りや経歴、暦は入れない
- この投稿には運用者がその土地の画像を付ける。imagePlace に「都道府県 画像に向く寺社や名所を2〜3個」を書く（例: 大阪府 住吉大社 大阪天満宮 難波神社）

**exclusion_hook（不安煽り型）のガイド**
- 1行目で、読み手がいま抱えている不安や痛みを言い当てる（「もう無理かも」と思った直後の方／粗末に扱われてきた方／答えを聞く覚悟のある方にしか届きません）
- 煽ったままにしない。2〜4行目で受け止める（それは復讐ではなく、天が流れを整えるだけ／弱さではなく、持ちこたえた証）
- 名乗りや経歴は出さない。短く、断定で言い切る。条件や保険をつけない
- 合図はひとつ（土地名か絵文字）。求めない締めでもよい
- 誇大な脅しはしない。不安は本人がすでに感じているものを言葉にするだけ。6〜12行

お手本（references）は 8 型で約 190本。超バズ特化のお手本はすべて画像つき（文章だけの超バズは無い）。

### 14-2. 生成の共通ルールで変わったところ（5 章の差し替え）

- **参考投稿は「ほぼそのまま」使ってよい。** 変えるのは土地の名前、名義の名前、合言葉や絵文字、括弧の種類、一語の言い換え程度（例: 「兵庫県にいます」→「大阪府に来ております」）。参考に無い要素（名乗り、経歴、比喩、由来話、飾りの情景）を足さない。長さも参考と同じ程度。凝りすぎると属人の意味が消える。一人称と語尾だけ Persona に合わせる。直近の自投稿と同じ土地・合言葉・書き出しを続けない。
  - 骨格を使い回す名義（reuseWinners）の 5行はそのまま。
- お手本は「型ごとに 3本ずつ、日替わりで入れ替えて」渡す（登録順に並べ、日付から決めた位置から 3本。以前は先頭 6本に固定されていた）。プロンプトの見出しは「参考投稿（ほぼそのまま使ってよい。変えるのは土地・名前・合言葉・一語程度）」、上限 8本。
- 出力 JSON に `imageKind`（pair/single/空）、`imageGenre`（ストックの系統）、`imageNote`（系統の中の 1つ。漢字なら字）、`imagePlace`（土地移動・寺社訪問のとき「都道府県 寺社や名所 2〜3個」）を足す。
- プロンプトに足す節: 「画像ストック（在庫のある系統と中身）」「バズ特化型・霊視開始型に添えてもよい画像」「直前の投稿の成績（3時間後の表示と判定）」「運用者からの指示」。
- 「求めない」お手本、暦、いただいた声、1日の構成は変わらず。

### 14-3. 1日の組み立てで変わったところ（6 章の差し替え）

1. **本数は全名義 2〜5本**（`postsPerDay: "2-5"`）、**投稿できる時間帯は 0時〜24時**（`activeWindow: "00:00-23:59"`）。時間帯の重み（bands）は 24時間をカバーする形で残す。
2. **構成の要望（dayMix）は本数を固定しない。** 型の比率として繰り返す（バズ＋属人で 3本なら バズ・バズ・属人）。
3. **型をどの時間帯に置くかは日ごとにランダム**（早朝はバズ、深夜は属人、という固定をやめた）。
4. 落ち込み判定は「3時間後の表示」の判定の並びで見る（14-5）。3時間後の記録が 3本たまるまでは 6 章の中央値方式を使う。
5. **超バズを差し込む規則（15:30 の生成）**
   - 「まったく届いていない名義」（直近 30日に LINE 追加も 1,000 以上の投稿も無い）が、3日つづけて日の最高が 300 未満なら、その日は超バズ特化だけ（`superBuzzOnlyAfterDays` 既定 3。0 で止める）。
   - **集客が来ている名義（hasAudience）は超バズだけに絶対しない。** 2日つづけて日の最高が 1,000 未満なら、超バズを 1本挟み、属人とバズ特化を 1本ずつ残す（その日は 3本以上）。`superBuzzAfterDays` 既定 2。
   - `hasAudience` の判定: `persona.hasAudience === true`、または直近 30日に signups が 1件以上、または 1,000 以上の投稿がある。
   - 型を手で指定した日、返事で構成を決めた日、`noSuperBuzz` の名義には当てない。休んだ日は数えない。
6. ジッター、合言葉の交互、暦、口コミは変わらず。

### 14-4. 画像ストック（新設。`image_stock` コレクションと `/stock` 画面）

| 項目 | 意味 |
| --- | --- |
| `kind` | `single`（1枚）／`pair`（左右 2枚のくっつけ。1枚を左右半分に割って登録できる） |
| `genre` | 系統（漢字、鳥居、月、花、開運、龍 など）。自由な語 |
| `note` | 説明。漢字なら字そのもの（福、縁…）。土地の画像なら「大阪府 住吉大社」のように土地名 |
| `accountId` | null なら全名義で使う。入っていればその名義だけ（その名義では共通より先に使う） |
| `placeSpecific` | 場所が分かる画像（鳥居、富士山、寺社）。系統の語から自動で印、あとから直せる |
| `files[]` | `{fingerprint, path, contentType, bytes}`。バケットは投稿の画像と同じ、accountId は `stock` |
| `usedBy{accountId:{count,at,lastPostId}}`, `usedTotal` | 使用回数（名義ごと） |

画面: 種類→名義→系統の順に一覧。編集（系統・説明・名義・場所の印）、外す、まとめて登録（何枚でも。ドラッグで落とせる。1件ずつ説明を書ける）。

使い方の規則:
- **超バズ特化型は必ずストックから付ける。** AI が系統（と中身）を選び、系統が合う在庫からその名義でいちばん使っていないものを付ける。合う在庫が無ければ「画像が未準備」で保留（作り直しのときはどれかを必ず付ける）。
- **バズ特化型・霊視開始型は「付けたり付けなかったり」。** 直前の投稿に画像が付いていたら次は付けない、を繰り返す。付けるのは場所が分からない 1枚だけ。
- **属人型にはストックの画像を付けない。** 土地移動型・寺社訪問型は自動で付けず、「大阪の画像を入れてください（住吉大社、大阪天満宮、難波神社など）」と案内して保留にする。人が承認のときに付ける。ストックに土地名の合う画像があれば案内に添える。
- **人が投稿に付けた画像は、その名義のストックに自動で残す**（系統は土地名か求めていた系統、無ければ「手付け」。土地移動・寺社訪問で付けたものは場所の印つき）。
- 使い回しは構わない。同じ画像を別の名義で使うのも可。

### 14-5. 表示数の「1時間後・3時間後」と良い・悪い（新設。`impressions.mjs`）

- 5分ごとの処理で、投稿の 1時間後と 3時間後に views/likes/replies を取り、`history`（と `posts`）に `snap1h`, `snap3h`, `verdict3h`（`verdict1h`＝1時間後にバズの線を超えたとき）を残す。手で出した投稿も対象（返信の取り込みで直近の自投稿を Threads から読み直し、`history` に最小の記録を作る）。取れない投稿（リポスト等）は「取れなかった」印を付けて叩き直さない。
- **判定は全名義共通の絶対値。** フォロワー数や名義の平均・中央値と比べない。

| 3時間後の表示 | 判定 |
| --- | --- |
| 300未満 | 悪い（配信に乗っていない） |
| 300〜1,000 | 普通 |
| 1,000〜3,000 | 良い |
| 3,000以上 | バズ |

- 線は `settings/impressions {bad, good, buzz}` で変えられる（`npm run ops -- lines --bad 300 --good 1000 --buzz 3000`、相談の `set_impression_lines`）。
- 「悪い」が 3本つづいた名義は抑制中と見て本数を絞る。
- 画面: 投稿一覧の投稿済みに「1時間後 ◯ / 3時間後 ◯ 判定」、レポートの投稿表に 1h / 3h / 判定 の列。レポートの SYSTEM にも同じ線を書く。

### 14-6. 投稿ごとの切り替え（新設。`per-post.mjs`）

本人の表: **悪い → 超バズ特化かバズ特化（超バズを使わない名義・ストックが無い名義はバズ特化）／普通 → バズ特化／良い・バズ → 属人。属人で 1,000 付いたらバズ扱いで属人を続ける。雅は当分、超バズ特化のみ。**

- 5分ごとに、これから 125分以内に出る投稿（pending/approved、未確認）を見る。名義の直近 24時間で 3時間後の判定がある最新の投稿を「直前」とし、表で次の型を決める。
- 段（超バズ／バズ／属人）が同じなら何もしない。違えば、その 1本だけを同じ時刻・同じ枠で作り直す（`generateForAccount` に types と slots を渡す）。元は却下（理由を残す）。新しい投稿に `switchedFrom`, `switchReason`, `autoApprove: true`。
- 作り直しで超バズになった投稿は、系統の画像が無くてもストックのどれかを必ず付ける。
- **自動承認**: `autoApprove` の投稿は、投稿時刻を迎えて承認待ちなら自動で承認して出す。画像が要るのに無いものだけ承認しない。
- 当てない名義: 超バズ特化だけの名義（dayMix が全部 image_buzz）、`perPostSwitch=false`、停止中。型を固定した投稿（`lockedType`）も当てない。
- 23:30 の自動仕分けは変わらず（承認待ちの文章だけ・画像つきは承認、画像が要るのに無いものは却下）。

### 14-7. その他の変更

- **土地移動型・寺社訪問型**は AI が `imagePlace` を出し、ツールは「◯◯の画像を入れてください（寺社や名所の候補）」を imageBrief に書いて `held`（画像が未準備）にする。人が画像を付けると承認待ちに戻る。
- **返信の取り込み**: 15分に 1回、名義ごとに Threads から直近 72時間の自投稿を読み直し、手で出した投稿のコメントも拾う（以前は翌朝の取り込みまで拾えなかった）。停止中でも自動返信 ON の名義は取り込む（「投稿は手で、返信は自動」）。
- **投稿の失敗**: 画像つきのコンテナ作成が失敗したら 10秒後に一度だけ作り直す。
- **signups**: `{date, accountId, accountName, count, enteredBy, source}`（ID `accountId_date`）。LINE 公式の「友だち追加」の日ごとの増分を入れる。LINE の数字は前日の投稿に対応する（1日遅れ）。
- **personas に足した項目**: `hasAudience`, `superBuzzAfterDays`（既定 2）, `superBuzzOnlyAfterDays`（既定 3）, `perPostSwitch`（既定 true）, `noSuperBuzz`。`dayMix` は比率。
- **posts に足した項目**: `imageKind`, `imageGenre`, `imageNote`, `imagePlace`, `stockId`, `snap1h`, `snap3h`, `verdict1h`, `verdict3h`, `verdictEarly`, `autoApprove`, `switchedFrom`, `switchReason`, `lockedType`, `preSwitchCheckedAt`, `preSwitchNote`, `requeuedAt`。
- **history に足した項目**: `snap1h`, `snap3h`, `verdict3h`, `verdict1h`, `verdictEarly`, `source`（manual/tool）。
- **相談の道具に足したもの**: `set_impression_lines`。`update_persona` に `hasAudience`, `superBuzzAfterDays`, `superBuzzOnlyAfterDays`。
- **ops の命令に足したもの**: `lines`。
- **定期実行（publish の相乗り）の順番**: 23:30 の自動仕分け → 作り直した投稿の自動承認 → 投稿 → 投稿ごとの切り替え → 03:20 の反応取り込み → 1時間後・3時間後の取得 → 反応 0 のバズ型の削除。

### 14-8. 運用の決まり（本人の言葉。CLAUDE.md と docs/claude-memory にも同じ）

- いちばん見るのはインプレッション。判定はフォロワー・平均・中央値と比べない。
- 集客（LINE 追加）が来ている名義には権威性があるので、超バズだけは必ず NG。落ちたら「超バズで様子見＋属人＋バズ特化」を全部入れる。超バズだけにしてよいのは一回も集客が来ていない名義（雅、凜、鈴木の名義）だけ。
- 属人型は伸びにくいのが基本。属人型は貴重。1名義の底は 1日 4〜13件の登録、そこに属人のバズで 20〜30件が乗る。名義を横に増やして底を積む。
- LINE の実データ: 純バズのコメントは登録率 3%、属人（名乗り・霊視開始・暦）のコメントは 20〜40%。4本に増やして同じ書き出しを繰り返した 2〜3日後に表示が 1/10 に落ち、登録も落ちる。
- 参考は「この程度」で使う（兵庫版→大阪版）。名義の色を出しすぎると属人の意味がなくなる。
- 数字は 0〜9 の数字。飾りの記号は禁止。合言葉は絵文字 1つか 2文字以内。
- 同じ文面・同じ画像の使い回しは構わない。

### 14-9. 画像ストックの持ち運び（`stock:export` / `stock:import`）

仕様書には画像は入らないので、ストックは書き出して持っていく。

```bash
# 本家で
npm run stock:export -- --out ./stock-export     # files/ と manifest.json（種類・系統・説明・名義名・場所の印）
# 持っていく先（同じリポジトリ、別の .env.local）で
npm run stock:import -- --from ./stock-export    # バケットに保存し image_stock に登録。同じ画像は飛ばす。名義は @ユーザー名で照合、無ければ全名義
```
