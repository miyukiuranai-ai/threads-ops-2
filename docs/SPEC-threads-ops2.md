# threads-ops2 仕様書

Threads の複数名義を、Threads 公式 API だけで自動運用するツール。
本家 threads-ops と同じコードから作り、データも定期実行も完全に別に動かしている。
この文書は、本家ともう1つのツールとの違いを把握するために書いた。

---

## 1. 本家との違い（ここだけ読めば分かる）

中身の仕組み（生成の考え方、投稿の型、評価の物差し、返信の流れ）は本家と同じ。違うのは次の点だけ。

### 1-1. 置き場所が別

| | 本家 threads-ops | threads-ops2 |
| --- | --- | --- |
| 画面の URL | threads-ops-app.vercel.app | threads-ops-2-rosy.vercel.app |
| Firestore | threads-ops-66d1d | threads-ops-2-c75bf |
| 画像の置き場（Storage） | 本家のバケット | threads-ops-2-c75bf.firebasestorage.app |
| Vercel | 本家のプロジェクト | 別プロジェクト |
| 5分おきの処理 | 本家の Apps Script | 別の Apps Script（2本のトリガー） |
| Meta のアプリ | 本家のアプリ | 別のアプリ（共用も可） |

名義・投稿・コメント・履歴・レポートは一切共有しない。片方を触っても、もう片方には何も起きない。

### 1-2. 見た目が違う

- 配色: 本家はベージュ地に緑。threads-ops2 は白地に濃い紺のサイドバー、青いボタン。
- 名前: 左上と画面の見出しが「threads-ops2」。
- サイドバーの名義の一覧は、その枠の中だけで上下に動く（名義が多くても、ページのメニューが隠れない）。

### 1-3. threads-ops2 だけにある機能

| 機能 | 内容 |
| --- | --- |
| 投稿の自動承認 | 設定 → 「投稿の承認」を ON にすると、生成した投稿案が承認待ちを飛ばして承認済みで保存される。本家は必ず人が承認するか、23:30 の自動仕分けを待つ |
| 画像が必要な投稿へ自動で画像 | 「画像が必要」と判定された投稿は、型や名義を問わずストックから自動で付く。本家は超バズ特化型とバズ特化型だけ |
| キャラ設定の削除 | 使っていないキャラ設定を画面から消せる。本家は消せない |
| 担当ごとの生成 | `npm run gen -- --group keidai` で、その担当の名義だけまとめて作れる |
| 既存の投稿案へ画像を後付け | `npm run stock:fill` |
| 構成を「割合」として扱う | 1日の構成（dayMix）は型の割合。本数が構成の数と違っても、その日の本数に割合で割り振る（属人3＋バズ2で3本の日なら属人2＋バズ1）。属人系に複数の型を並べると日替わりで順ぐりに使う。本家は構成の数がそのまま本数になり、本数が少ない日は先頭の型（バズ寄り）に偏る |
| 割合をまとめて設定 | `npm run mix -- --accounts 名義1,名義2 --ratio 6:4 --posts 3-4`。`--group 担当` でまとめて、`--dry` で確認だけ、`--reset` で解除 |
| 最初の設定を助けるコマンド | `npm run env:init`（.env.local を鍵ファイルから作る）、`npm run setup:check`（接続を1つずつ確認）、`npm run db:migrate`（古いデータの形を直す） |
| 環境変数の確認ページ | `/api/cron/health` で、どの環境変数が入っているかを値を出さずに確認できる |

### 1-4. 本家にあって threads-ops2 で変えたもの

- `npm run storage:setup` が許可する URL を threads-ops2 のものにした（本家の URL のままだと画像をアップロードできない）。
- 開発中に画面の左下へ出る Next.js のマークを消した。

## 2. 何をするツールか

- Threads の複数名義（占い師）を、公式 API だけで運用する。ブラウザの自動操作はしない。
- 投稿文は Claude が作り、人が承認してから投稿する（自動承認を ON にすると人の承認を飛ばせる）。
- コメントには自動で返信し、プロフィールのリンクへ誘導する。
- 最終目的は LINE の友だち追加。反響（表示・いいね）ではなく登録で判断する。
- 他人の投稿の検索やプロフィール取得は使わない（Meta の App Review を受けない運用）。

## 3. 技術の構成

| 項目 | 内容 |
| --- | --- |
| 画面 | Next.js 15（App Router、JavaScript）。Vercel で動かす |
| データ | Firestore（firebase-admin） |
| 画像・動画 | Firebase Storage。非公開のまま、投稿のたびに期限つきの URL を作る |
| 生成 | Anthropic の Claude。既定は claude-opus-5、名義ごとに claude-sonnet-5 も選べる |
| ログイン | ID とパスワード。署名付きクッキー（30日） |
| 定期実行 | Vercel Cron 2本 ＋ Google Apps Script 5分おき 2本 |

## 4. 1日の流れ（日本時間）

| 時刻 | 何が起きるか | 誰が動かすか |
| --- | --- | --- |
| 15:30 | 前日のレポートを作り、翌日ぶんの投稿案を全名義ぶん作る | Vercel Cron |
| 15:30〜 | 人が「投稿予定」で本文を直し、承認する（自動承認が ON なら不要） | 人 |
| 5分おき | 承認済みで予定時刻が来たものを投稿。コメントの取り込みと返信 | Apps Script |
| 23:30 | 承認されないまま残った投稿案を仕分ける（文章だけ→承認、画像が要るのに無い→却下） | 5分おきの処理に相乗り |
| 03:20 | 前日の投稿の表示数・いいね・コメントを取り込む | 同上 |
| 毎日 | 投稿の1時間後と3時間後の表示数を記録し、良い・悪いを判定 | 同上 |
| 06:00（UTC 21:00） | 名義のトークン（60日）を延長 | Vercel Cron |

Vercel Cron は 30 分ほど遅れることがある。

| バズ特化 | buzz_engagement | バズ特化型 | リーチ確保。いいねを条件に組み込む |

## 6. 投稿の評価

- いちばん見るのは表示数（インプレッション）。フォロワー数や名義の平均とは比べない。
- 全名義共通の絶対値で判定する。3時間後の表示が 300未満は悪い、300〜1,000は普通、1,000〜3,000は良い、3,000以上はバズ。
- 線は画面の「相談」か `npm run ops -- lines` で変えられる。
- 取れ高は LINE 追加数 ÷ 表示 × 1万。
- 直前の投稿の判定で次の型を決める（悪い→超バズかバズ特化／普通→バズ特化／良い・バズ→属人）。

## 8. データ（Firestore の主なコレクション）

accounts（名義）、personas（キャラ設定）、posts（投稿案）、replies（コメント）、replyTemplates（返信の文面）、replyCursors・replyStats（返信の進み具合）、commenters（コメントした人の集計）、history（投稿と反応）、image_stock（画像ストック）、media（画像の指紋）、references（お手本）、testimonials（お客様の声）、watchlist（監視リスト）、signups（LINE 追加数）、directives（その日の指示）、reports（日次レポート）、chat_messages（相談）、runs（実行ログ）、settings（表示数の線・Anthropic の残高・投稿の自動承認）。

## 9. 自動承認（threads-ops2 だけ）

設定 →「投稿の承認」で ON / OFF を切り替える。既定は OFF。

ON のときの動き:
- 15:30 の生成でできた投稿案が、そのまま承認済みで保存される。
- すでに承認待ちで残っている投稿案も、5分おきの処理が見つけしだい承認する（ON にする前に作られた分の取りこぼしを防ぐ）。
- 予定時刻が来ると、5分おきの処理が投稿する。
- 画面で本文を直したり却下したりは、これまで通りできる。

ON でも承認せず止めるもの:
- 画像が要るのに素材が無い投稿（保留のまま。画像を付けると承認待ちに戻る）。
- 名義の設定で「自動仕分けから外す」を ON にした名義（人が全件見る運用）。

投稿モードが live のときに ON にすると、人が見ないまま Threads へ出る。切り替えるときに確認を出す。

## 10. 画像の付き方

| 型 | 画像 |
| --- | --- |
| 超バズ特化型 | 必ずストックから自動で付く。系統（漢字・鳥居・月など）を AI が選ぶ |
| バズ特化型・霊視開始型 | 付けたり付けなかったり。直前に付けていたら次は付けない。場所が分からない1枚だけ |
| 土地移動型・寺社訪問型 | その土地の画像。ストックに土地の合うものがあれば自動、無ければ別の1枚を仮に付ける |
| その他の属人型 | 原則なし。ただし「画像が必要」と判定された投稿にはストックから自動で付く |

キャラ設定の「画像の頻度」を never にすると、その名義では画像の指示自体が出なくなる。

## 12. 安全と費用

- 投稿は必ずガードを通る（POSTING_MODE、名義の稼働状態、トークンの期限）。1名義の失敗で他は止まらない。
- POSTING_MODE は dry_run が既定。live にするまで Threads へは何も出ない。
- 生成は1名義1日あたり、Opus でおよそ15円、Sonnet でおよそ6円。投稿・返信・削除は Threads API のみで無料。
- Firestore と Storage は、この規模なら無料枠か月に数十円程度。
- 秘密情報はコードに書かない。`.env.local` と Vercel の環境変数だけに置く。
